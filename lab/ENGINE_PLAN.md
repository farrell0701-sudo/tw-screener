## 3. 新引擎設計

### 3.1 原則
1. **所有東西都在 repo 的工作樹裡**（`lab/`），不再有 repo 以外的工作目錄。
2. **每個實驗結束就提交並推送**：登記簿、腳本、結果摘要。中間快取可重建，不入庫。
3. **沒有事前登記就不能跑**：執行器先檢查登記簿裡有該編號，否則拒絕執行。
4. **單一面板**：2004–2026 一份資料，不再拆成新舊兩段各自載入（先前為了省記憶體而拆，改用 float32＋分欄存檔解決）。
5. **每個規則條件都是可開關的參數**，方便做條件減法與高原檢查。

### 3.2 結構
```
lab/
  setup.sh            從資料分支解壓 → 建還原價 → 建面板（一次完成）
  data/build_clean.py 未還原價＋事件 → 還原因子
  data/panel.py       → cache/panel/*.npy（float32）：O H L C RC V AMT、可交易旗標、瑕疵日、產業、指數
  core/feat.py        個股自身交易日的指標（ATR、EMA、布林、區間…），結果落地快取
  core/signals.py     T_ld、強勢池、X1 候選與排序、V4.1 事件；每個條件一個開關
  core/sim.py         runX（X1）、runV（V4.1）：隔日開盤、漲跌停、成本、停損、路徑擾動
  core/evalu.py       年化、回撤、Calmar、Sharpe、時間區塊 bootstrap、合併、高原表
  core/run.py         實驗執行器：檢查登記 → 跑 → 存結果摘要 → 寫回登記簿 → git commit ＋ push
  registry/           registry_L.md、registry_M.md
  exp/                每個實驗一支腳本（L109.py…）
  results/            每個實驗的路徑平均日報酬（壓縮，小檔，入庫）
  cache/              面板與指標快取（.gitignore，不入庫）
```

### 3.3 重建時一併修正的已知問題
- 下市／長期停牌部位會永久佔住名額（L-106 X8 的異常）。處理方式見 L-113 第 3 點（2026-11-18 改）：停牌繼續持有、以最後價估值、佔名額，恢復後依原規則出場；下市在下市日才回收資金，出清價做 0%／50%／100% 折扣敏感度。
- 興櫃期間與還原後超過漲跌幅的瑕疵日：建面板時標記，進可交易池前要求近 250 根乾淨。
- 2016 年資料中斷的 85 檔（審核報告第 9 項）：建面板時列出清單，逐檔確認。
- 加權指數不含股利：評估時另外提供含股利近似，避免超額被高估。
